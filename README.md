# claude-code-accounts

Use several Claude subscriptions with Claude Code on one Mac, for example a work Team plan,
a client organization's Team plan and a personal Pro/Max plan. The account is picked
automatically from the folder you start `claude` in. That works in a terminal and in IDE
integrations that start Claude without a shell, such as JetBrains Air.

```
~/Code/client/...    → ~/.claude-client    (second organization)
~/Code/personal/...  → ~/.claude-personal  (personal subscription)
anywhere else        → ~/.claude           (default account, also the settings "base")
```

This repo is a reference for redoing the setup, not a polished tool. Read the scripts before you
run them.

## How it works

- Claude Code has no per-project account setting. The documented mechanism is one config
  directory per account, selected with `CLAUDE_CONFIG_DIR`
  ([docs: "Log in with multiple accounts"](https://code.claude.com/docs/en/authentication)).
  On macOS each config dir gets its own Keychain entry (`Claude Code-credentials-<hash>`), so every
  account stays logged in at the same time.
- Project and local settings can't set `CLAUDE_CONFIG_DIR`. It has to be in the environment of
  whatever starts `claude`.
- [`bin/claude`](bin/claude) is a wrapper that sits first on `PATH`. It reads the working directory
  (`pwd -P`), exports the `CLAUDE_CONFIG_DIR` from its `ACCOUNTS` list (unless one is already set),
  and `exec`s the real `~/.local/bin/claude`.
- **Why a script and not a shell function or alias:** JetBrains Air starts Claude by absolute path,
  without a shell. It resolves `claude` on `PATH` once, from the shell environment the IDE loads at
  startup, and caches it in
  `~/Library/Application Support/JetBrains/<IDE><version>/options/air.agentCliAvailability.xml`
  (`resolvedExecutablePath`). A function would never run. With the wrapper first on `PATH`, a
  restart of the IDE makes Air resolve the wrapper instead.
- `~/.local/bin/claude` is a symlink owned by the native auto-updater, so the wrapper lives in
  `~/.local/claude-switch/bin` and doesn't replace it.

## What is shared and what is per account

`~/.claude` (the default account) is the base. Each extra account dir is set up like this:

| Item | Handling | Why |
| --- | --- | --- |
| `CLAUDE.md`, `agents/` | Symlinked to `~/.claude`. | Same global instructions and subagents everywhere. |
| `ide/` | Symlinked to `~/.claude/ide`. | The IDE writes its `/ide` lock files there. |
| `skills/` | Real dir per account. Your own skills are symlinked one by one. | claude.ai organization skills sync into `skills/synced/<org>_<account>/`. A shared dir mixes organizations' skills together. |
| `settings.json` | Generated by [`bin/sync-settings`](bin/sync-settings) from `~/.claude/settings.json` minus an exclude list. The wrapper re-syncs it whenever the base is newer. | A symlinked copy leaks work-only plugins: a marketplace in `extraKnownMarketplaces` with its plugins in `enabledPlugins` gets auto-installed into every account. |
| `.claude.json` | Per account. Never link it. | Holds the login (`oauthAccount`), user-scope MCP servers and UI preferences. |
| User-scope MCP servers | Copied with `claude mcp add-json -s user`. | They are stored in `.claude.json`. |
| Plugins | Installed per account (`claude plugin install`). | Plugin installs belong to one config dir. |
| A few UI preferences | Copied once from `~/.claude.json` (Chrome on by default, spinner tree, diff sidebar, ...). | They live in `.claude.json`, not in `settings.json`. |
| Statusline caches | Key them by `${CLAUDE_CONFIG_DIR:-$HOME/.claude}`. | A custom statusline that caches rate limits under `~/.claude` otherwise shows one account's limits in another. |

### sync-settings

- Edit `EXCLUDE` at the top of the script. It holds glob patterns per section (`enabledPlugins`,
  `extraKnownMarketplaces`, `pluginConfigs`) for entries that must stay in the default account.
- It deep-merges and the base wins. Keys that exist only in an account's file are kept, so a
  setting changed inside an account (e.g. `/config`) survives until the base defines the same key.
- This matters because tool installers that add Claude Code hooks usually write only to
  `~/.claude/settings.json`. The wrapper carries those changes over automatically.

## Files

| File | Installed to | Purpose |
| --- | --- | --- |
| `bin/claude` | `~/.local/claude-switch/bin/claude` | Folder → account wrapper. Edit `ACCOUNTS`. |
| `bin/sync-settings` | `~/.local/claude-switch/sync-settings` | Builds an account's `settings.json`. Edit `EXCLUDE`. |
| `install.sh` | (not installed) | Copies the two files above and adds the `PATH` line to `~/.zshrc`. Idempotent. |
| `setup-account.sh` | (not installed) | Creates or re-aligns an account dir: links, skills, settings, MCP servers, marketplaces, plugins, preferences. Idempotent. |

`install.sh` copies rather than symlinks, so moving or deleting this repo can't break `claude`.
Re-run it after editing anything in `bin/`.

## Setup

1. Edit `ACCOUNTS` in `bin/claude` and `EXCLUDE` in `bin/sync-settings`.
2. Install and create the account dirs:

   ```sh
   ./install.sh
   ./setup-account.sh ~/.claude-client
   ./setup-account.sh ~/.claude-personal
   ```

3. Open a new terminal and restart your IDE.
4. In a folder for each account, run `claude`, then `/login`, then `/status` to confirm the
   account.

Adding an account later is the same thing: add a line to `ACCOUNTS`, run `./install.sh`, run
`./setup-account.sh ~/.claude-<name>`, then log in.

## Verify

```sh
# What the IDE resolves (it loads a login + interactive zsh):
zsh -lic 'command -v claude'          # → ~/.local/claude-switch/bin/claude

# Which account a running session uses (no output = default ~/.claude):
ps eww -o command= -p <pid> | tr ' ' '\n' | grep CLAUDE_CONFIG_DIR

# JetBrains Air's cached executable:
grep -A1 '"claude"' ~/Library/Application\ Support/JetBrains/*/options/air.agentCliAvailability.xml
```

Inside a session, `/status` shows the account and organization.

## Gotchas

- **These env vars override the switch:** `ANTHROPIC_API_KEY` and `CLAUDE_CODE_OAUTH_TOKEN` take
  precedence over the Keychain login, so changing config dirs does nothing while they're set.
- **Air still using the old path:** quit the IDE completely, set `resolvedExecutablePath` in
  `air.agentCliAvailability.xml` to `~/.local/claude-switch/bin/claude` (only while the IDE is
  closed, or it writes the old value back), then start it. A plain restart is usually enough.
- **Session history is per account** (`<config dir>/projects`). Sessions that ran under another
  account before the switch don't show up in `--resume`.
- **Claude in Chrome pairing is per account.** Pair once in each account on first use.
- **Base-only settings apply to every account.** Something like `disableClaudeAiConnectors` set in
  the base reaches all accounts. To change it for one account, remove it from the base and set it
  per account.
- **A fresh config dir lacks the official marketplace** (`claude-plugins-official`) until its
  first interactive start. `setup-account.sh` adds it up front when an enabled plugin needs it.
- **Console sign-ins aren't separated.** Claude Console logins without an API key are stored
  outside the config dir (per the docs). This setup only covers claude.ai subscription logins.

## Uninstall

1. Remove the `PATH` line from `~/.zshrc`, delete `~/.local/claude-switch`, and restart the IDE.
2. Optionally delete the extra account dirs, and their `Claude Code-credentials-<hash>` entries in
   Keychain Access.
